# Security review notes

Release-candidate review of the implementation against its threat model, done offline with a scripted fake model on Linux, Node v26.8.2, Playwright 1.64.1. Each row names the control, where it lives, the test that holds it, and what remains. "Not verified" means no live provider, outside environment, or Node 24 run has checked it.

Scope and trust boundary: the cohort is a local tool for trusted application targets with synthetic data. Setup modules are trusted local code with your process privileges. Browser interception is a guardrail, not a network sandbox. Remote or Docker hosting is unsupported.

| Threat | Control (code) | Held by (tests) | Remaining risk |
| --- | --- | --- | --- |
| Page prompt injection | Fixed system instructions; the model sees placeholders, never secret values; tools are schema-validated; navigation allowlist (`src/core/agent.ts`, `src/core/tools.ts`, `src/core/engine.ts`) | `agent.test.ts` injection page (`goto` to an exfiltration host is refused); persona generator injection (`persona.test.ts`) | The agent can still follow misleading in-scope instructions |
| Secret leakage to provider | Fill-only substitution, masked capture with change tracking, outbound text scan that fails closed (`src/browser/observations.ts`, `src/setup/secrets.ts`) | PNG pixel canaries and outbound scans in `agent.test.ts`, `run.test.ts`; `canary.test.ts` | Transformed, encoded, or canvas-rendered secrets; script-set `.value`, late or closed shadow roots ([compatibility.md](compatibility.md#secret-boundary)) |
| Secret leakage in artifacts | Redaction of reports, steps, replay, resolved config; owner-only modes; gitignore from `cohort init`; trace warnings | `canary.test.ts` scans every file under `.cohort` except `trace.zip` for setup secrets, an env-only value, and the provider key (plain and base64), checks 0700/0600 modes, and confirms the trace does hold the filled value | `trace.zip` holds secrets by design; screenshots can show sensitive app content |
| Wrong application or real side effects | Start-URL scheme/credential checks, explicit origins, no payment or CAPTCHA automation | `run.test.ts`, `agent.test.ts` navigation and blocker tests | The owner must point the lab at a safe environment |
| Navigation and request escape | Context route guard, CDP redirect-hop guard, response backstop, popups closed and their requests aborted, service workers blocked (`src/core/engine.ts`) | Redirect, popup, frame, and route tests in `agent.test.ts`, `run.test.ts` | WebSockets and redirects inside out-of-process frames are not intercepted (backstop ends the run); not a network sandbox |
| Local API compromise | Random 256-bit token in a URL fragment, Host and Origin checks, JSON-only mutations, no CORS (`src/dashboard/server.ts`) | `dashboard.test.ts` (401/403/421, rebinding Host, cross-site fetch metadata) | Local malware can read the process or the token |
| Dashboard XSS | Escaped text, sanitized Markdown, strict CSP with no inline code, report HTML served sandboxed (`src/dashboard/server.ts`, `src/evidence/report.ts`) | `dashboard-ui.test.ts` (CSP violations fail the suite, persona names render as text), `report.test.ts` escaping | Browser or library vulnerabilities |
| Trusted setup abuse | `.cohort/setup/` containment, symlink refusal, API rejects setup-reference edits, no model-authored modules (`src/config/files.ts`, `src/config/editable.ts`) | `config.test.ts` path and symlink tests, `dashboard.test.ts` setup-reference tests | Setup code runs with your privileges |
| Excessive spend | Dated catalog prices, reservations, step/time/dollar caps, explicit unknown-cost status (`src/core/cost.ts`, `src/core/estimate.ts`) | `core.test.ts`, `agent.test.ts` cap and reservation boundaries | Unpriced models: dollar cap unenforceable and stated so; an in-flight call can overshoot reported spend |
| Provider key disclosure | Keys read only by adapters; booleans across the API; scrubbed errors (`src/providers/types.ts`; setup scrub composition in `src/setup/session.ts`); unexpected-error output scrubbed (`src/cli.ts`) | `providers.test.ts` error paths, `setup-session.test.ts`, `dashboard.test.ts` canaries, `canary.test.ts` (CLI output, every artifact) | A provider error that echoes a masked key fragment is kept (up to 500 chars); the local process is trusted |
| Wrong model or comparison drift | Catalog validation, availability, vision and effort checks, frozen snapshot across repeats (`src/providers/catalog.ts`, `src/config/resolve.ts`) | `catalog.test.ts`, `config.test.ts`, `dashboard-ui.test.ts` pickers | Owner-edited rates and capabilities may be stale |
| Misleading UX claims | Exact outcome states, labelled opinions, evidence-required claims (`src/evidence/friction.ts`) | `report.test.ts`, `run.test.ts` | Synthetic behaviour is not validated against people |
| Replay injection | Fixed templates, structured locators, escaped literals (`src/evidence/replay.ts`) | `core.test.ts` locator literal and replay-generation cases | Trusted setup remains executable |
| Brittle replay | Stability labels, no healing, explicit replay status | `journey.test.ts`, `run.test.ts` replays | A recorded run does not guarantee future replay |
| False or misleading PR verdicts | `cohort compare` replays the hash-pinned approved script unchanged, confirms a head failure with a second round, and requires complete provenance plus hooks that verify the served revision, the head deployment, and a reset scoped to each execution; anything else, including base failures, is `inconclusive`, and only a confirmed regression exits 1 (`src/core/compare.ts`) | `core.test.ts` exhaustive classification; `compare-regression.test.ts` and `compare-hooks.test.ts` regression, healthy, flaky, missing provenance, unverified and contaminated resets, wrong deployment, failing cleanup | Four executions do not rule out rarer flakiness; hooks are trusted to report identity and reset truthfully; a broken head deployment that still serves pages reads as a regression |
| Secrets in PR comments | Bare-origin `--base`/`--head` (no path, query, or credentials), the replay redaction of Playwright output, Markdown escaping, text-only evidence (`src/core/compare.ts`, `src/core/replay.ts`) | `compare-regression.test.ts` setup-secret and provider-key canaries in output and the comment body | App text inside a failing locator or error line is posted as written |
| Cross-run contamination | Fresh contexts, scoped setup, cleanup, no resume | `run.test.ts` repetition isolation | The application must support independent data |
| Artifact traversal or tampering | Generated IDs, plain-directory and regular-file checks, manifest IDs only, per-artifact SHA-256 in the manifest; `cohort replay` and `cohort compare` verify every file and refuse files a run never writes; compare also and pins `manifest.json`, and with it every file's hash, to `--approved` (`src/evidence/bundle.ts`, `src/evidence/manifest.ts`) | `report.test.ts`, `dashboard.test.ts` traversal and symlink tests; `compare-regression.test.ts` tampered script, planted `playwright.config.ts` and `x.tmp-0/replay.spec.ts`, missing file, unapproved script, forged `resolved-config.json` with a matching manifest entry | Local bundles stay mutable; only `--approved` binds a downloaded bundle to the approval |
| Provider retention | OpenAI requests set `store: false`; minimal payloads (latest image only) | Fake-server contract tests | Not verified live; retention is the provider's policy |
| Browser or dependency compromise | Exact-pinned runtime deps (Playwright, `yaml`), lockfile, Dependabot | CI `--frozen-lockfile` | No hostile-site security guarantee |
| Privileged PR execution | The Action takes no keys as inputs, never interpolates inputs into shell, uploads nothing, and does not comment; the documented compare workflow is same-repository only, starts with empty permissions, checks out the base revision so hooks and setup modules come from trusted code, and posts from a separate job that holds only `pull-requests: write` and no keys; `cohort publish` rechecks the PR head and repository before writing (`action.yml`, `action/run.ts`, `src/core/publish.ts`) | `action.test.ts` workflow shape; `publish.test.ts` stale head, fork, single updated comment, token never printed | Workflow authors must not run it on untrusted fork code with secrets ([compare.md](compare.md#trusted-workflow)) |
| Public remote exposure | Loopback default, explicit `--host` with a printed warning, token still required | `dashboard.test.ts` | Plain HTTP; remote hosting unsupported |

## Changes made in this review

- `trace.zip` is now chmod 0600 after writing. `cohort ui` chmods `.cohort` to 0700 and `index.sqlite`, `-wal`, and `-shm` to 0600 on every start, so an index left with umask modes is tightened too; `cohort init` creates `.cohort` as 0700. Before, `.cohort` and an existing index followed the umask, typically 0755/0644 (`canary.test.ts` holds this).
- Unexpected CLI errors print one bounded line with provider keys scrubbed instead of a raw stack; `COHORT_DEBUG=1` restores the stack.
- `cohort init` writes `.cohort/.gitignore`; `cohort doctor` reports when `.cohort/runs`, `.cohort/auth`, or `.cohort/index.sqlite*` is not ignored and when `.cohort/auth` is group- or world-readable.
- The build now starts from an empty `dist/`, so deleted modules cannot ship from a stale build.

## Not verified

- Provider wire formats, retention settings, and error bodies against live APIs.
- Node 24, locally or in CI (CI pins Node 24 but has never run; local runs used Node v26.8.2).
- The Action on GitHub-hosted runners.
- Other browsers for the dashboard; Chromium only.
