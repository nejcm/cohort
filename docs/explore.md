# Exploring an app

`cohort explore` runs one bounded exploration of a web app and suggests personas, goals, and replay tests from what it actually saw. It never saves anything outside its own run bundle until you review and save a suggestion.

```sh
cohort explore --url https://staging.example.test/ [--steps 40] [--time-ms 600000] [--dollars 2] [--max-usd 10] [--detach]
```

## What it does

1. **One ordinary run.** The ad-hoc first-time user gets a fixed exploration goal. The same origin allowlist, routes, screenshot masks, secret redaction, and step, time, and dollar caps apply as for `cohort run`. It takes the usual `--mode`, `--model`, `--effort`, `--steps`, `--time-ms`, `--dollars`, `--max-usd`, `--allow-unpriced`, and `--allow-untested`; it refuses `--persona`, `--tag`, `--suite`, `--note`, and `--repeats`. The run is indexed like any other, so `cohort runs list|show|wait|cancel` and `cohort report` work on it.
2. **Destructive controls are refused.** During exploration, the harness refuses a click on, or Enter/Space on the focused, control whose visible text looks like a delete, payment, or account change (for example "Delete", "Pay", "Checkout", "Unsubscribe", "Change password"). Visible text means the accessible name, label, placeholder, or button value, whichever locator reaches the control. Enter or Space is also refused when the focused element cannot be identified. The step is recorded as `rejected action_refused`, and the run continues; the summary lists such steps as `untried`. Not checked: icon-only or unlabeled controls, non-English labels, a form submitted by pressing Enter in a text field, `fill` (including choosing a select option), and `goto` to a destructive URL. Point exploration at a disposable environment.
   Token-like start URL query and fragment values (20+ characters, or 8+ mixing letters and digits) are hidden before the first capture: masked in screenshots, redacted from steps, and refused in `goto`.
3. **One suggestion call.** After the run, one metered provider call reads the redacted step log and the last screenshot, then returns features, personas, goals, and tests. Each must cite step IDs. That call is capped at $0.50, and the cap is added to the batch estimate before `--max-usd` is checked.

With `--detach`, the run starts in the background. Wait for it and then run `cohort explore suggest <run-id>` to make the suggestion call.

## Evidence rules

Everything the model claims is checked against the run's own steps:

- A **feature** is dropped if any cited step does not exist, did not succeed, or has no after screenshot, or if its only evidence is the opening navigation. Each kept feature lists its step IDs and their screenshot IDs. A kept citation shows that the step happened, not that the sentence attached to it is true; review the prose.
- A **persona** must parse and validate as a [persona file](personas.md), must not set `setup`, `storageState`, `model`, `effort`, or `limits`, and must cite observed steps under the same rule.
- A **goal** must cite observed steps under the same rule and name a kept suggested persona. Goals become entries in one suggested suite.
- A **test** names the last step of a path. The harness takes the run's steps up to that step. It drops the test when that step fails the same rule, when the path includes a failed step, or when any step cannot replay. The kept test is generated by the same replay generator as `replay.spec.ts`. It is written as a file and never run.

Everything dropped is listed under `dropped` with a reason. Provider keys, and on a foreground run the start URL's query and fragment values, are removed from model output, generated specs, and the summary before they are written.

The summary is not exhaustive. Exploration covers only what the agent reached within its caps, and `coverage` says so.

## Files

Suggestions live inside the run bundle, `.cohort/runs/<run-id>/suggestions/`:

| File | Content |
| --- | --- |
| `explore.json` | The summary: `features`, `untried`, `personas`, `goals`, `suite`, `tests`, `dropped`, `coverage`, `estimatedCostUsd` |
| `personas/<id>.md` | Validated persona suggestions |
| `suite.yml` | Suite `explore-<suffix>` with one entry per kept goal; `defaults.url` only when the start URL had no query or fragment |
| `tests/<name>.spec.ts` | Playwright specs replaying an observed path; run them yourself with `npx playwright test` after review |

Running `cohort explore suggest` again replaces this folder.

## Saving after review

```sh
cohort explore save <run-id> --persona <id>          # prints the file and refuses: confirmation_required
cohort explore save <run-id> --persona <id> --yes    # creates .cohort/personas/<id>.md
cohort explore save <run-id> --suite <id> --yes      # creates .cohort/suites/<id>.yml
```

Saving uses the same validated atomic write as `cohort persona add`. If the file exists, saving fails with `conflict`. To replace it, pass the current `--revision <sha256>` from `cohort persona show <id> --json`. A stale revision also fails with `conflict`. Copy test specs by hand.
